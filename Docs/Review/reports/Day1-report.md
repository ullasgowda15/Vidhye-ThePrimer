### P1 — should fix today
- [ ] **`Beat` JSON Schema sends numeric constraints that structured outputs rejects.** `backend/apps/story/ai/schemas.py:54` declares `difficulty: float = Field(ge=0.0, le=1.0)`, which Pydantic emits as `"minimum": 0.0, "maximum": 1.0`. Verified by printing `beat_json_schema()`. The structured-outputs JSON-Schema subset does **not** support `minimum`/`maximum`/`multipleOf`. The SDK strips unsupported constraints only when you hand it a Pydantic model via `messages.parse(output_format=…)`; `router.py:100` passes the **raw dict** through `output_config.format.schema`, so nothing strips them and the API is likely to 400 on the first real call. Nothing in the test suite catches this — `tests/test_hello_beat_command.py:31` monkeypatches `generate_json`, so the live request shape is never exercised. **Fix:** drop `ge`/`le` from the schema sent to the provider and keep the 0–1 range as a post-validation check on the returned `Beat` (or pop the keys in `beat_json_schema()`), then re-run `manage.py hello_beat` with a real key to confirm end to end. This is the founder's headline manual test for the day.
- [ ] **CI has never run — there is no git remote.** `git remote -v` → empty; `gh run list` → not authenticated. Criterion 14 requires "CI is green", and `DEPLOY.md` lists it under what "deployable" means, but no workflow run can exist yet. The workflow *logic* is sound (reviewed line by line: correct service containers with health gates, migration check before migrate, staleness gates, ASGI + Celery smoke tests, Docker build). **Fix:** add the remote, push `e3a2b21`, and confirm the run is green before closing Day 1. Two things to watch on the first run: the `--detach`ed Celery worker with a fixed 10s `sleep` (CI-flaky if the runner is slow), and `mypy` is `continue-on-error: true` so type regressions will not fail the build.

### P2 — improvements (non-blocking, log for later)
- [ ] **PWA install prompt will not actually fire.** No service worker exists anywhere (`grep -rl "serviceWorker\|registerSW" src public` → nothing), and Chrome requires one with a fetch handler before `beforeinstallprompt`. Icons are also SVG-only; the conventional 192×192 and 512×512 PNGs are absent. The Day 1 brief explicitly says a service worker is optional and "do not over-invest", so this is correctly deferred — just don't let the manifest's presence read as "installable". Worth closing when the offline story is designed.
- [ ] **`interaction.type` is an unconstrained `str`** (`schemas.py:38`). PRODUCT.md §8.1 implies a bounded set (`count`/`choose`/`say`/`tap`/`none`), and the docstring lists exactly those five. An `enum` would let the provider constrain generation instead of relying on the prompt, and would make the Day 4 client's dispatch exhaustive. `enum` *is* in the supported structured-outputs subset.
- [ ] **`DEFAULT_PERMISSION_CLASSES` is globally `AllowAny`** (`config/settings/base.py:145`). Correct today (health is the only endpoint), but this is exactly the kind of default that silently outlives its justification. Flip it to `IsAuthenticated` with an explicit `@permission_classes([AllowAny])` on the health view when auth lands on Day 2.
- [ ] **`.env.example` omits two settings that `base.py` reads** — `AI_BEAT_MODEL` and `AI_PROVIDER_ORDER` (`base.py:187-188`). They have sane defaults so nothing breaks, but the example file is the discoverability surface for the AI layer's knobs.
- [ ] **`max_tokens = 8000` on Opus 5 covers thinking *plus* response text** (`router.py:34`). Thinking is on by default on that model. Fine for a single short beat, but worth re-checking once beats carry real memory/objective context, since truncation surfaces as a schema-validation failure rather than an obvious error.
