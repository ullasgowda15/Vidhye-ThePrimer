## What's working well

- **The cache is real and it was cheap to prove.** `render_companion` printing `generated: 0 / cache hits: 3` against the live Cloudflare adapter is the single best artifact of the day: it is an assertion a founder can re-run in five seconds that costs nothing and would go red the moment the cache broke. The lookup deliberately precedes provider *construction*, so a misconfigured key cannot even fail on a cache hit.
- **The scan-before-store ordering is structural, not remembered.** There is exactly one write path, the scan is in it, and the test asserts the *filesystem* is untouched on a block — not just the row count. `SafetyStatus.PENDING` exists purely so "never scanned" can never impersonate "scanned and fine".
- **`conftest.py` blanks every credential and pins both adapters to `local` for the whole suite.** CI has no keys but a developer's shell does, and a suite that quietly spends money on one machine and not in CI is the worst kind of test. I verified it: 184 tests, real `.env` with live Cloudflare/ElevenLabs/OpenRouter keys present, zero provider calls.
- **The smoke harness (`8e4b9c7`) is the right answer to the right problem.** The Day-3 unit tests prove the pipeline against a deterministic offline adapter — exactly the shape of test that cannot notice the pictures are placeholder SVGs. `make smoke-media` closes that with a real-raster assertion that explicitly rejects `image/svg+xml`, and it is credit-frugal by design. It is genuinely absent from CI and from pytest collection (verified: not in `testpaths`, not a `test_*.py`).
- **Identity is synchronous, art is asynchronous, and the split is load-bearing.** A parent gets their companion in one request; a broker outage costs art, not a friend (`views.py:128` logs the enqueue failure and moves on). `assets_ready` is deliberately "portrait + voice", not "all six", so the imprint moment is not held hostage by the *sleepy* expression.
- **The child never sees a spinner or an error, on Day 3.** `MeetCompanion` renders a sleeping, breathing friend while the art generates and *also* when the request fails outright — two tests pin both. That is Day 7's principle honoured three days early.
- **Determinism is treated as a cache property, not a style preference.** Prompt sections are emitted in fixed order, characters sorted by key, scene text is a module constant rather than generated, and `STYLE_VERSION` is inside the hashed string so editing the art direction invalidates every cached illustration in one step instead of interleaving two styles in one child's storybook.

### P1 — should fix today

- [ ] **The reference set never reaches the image model — consistency is carried by the descriptor alone.** `build_illustration_prompt` emits a `REFERENCES:` block containing a *local file path* (`apps/media/prompts.py:90-95`), and `CloudflareImageProvider.generate` sends `{"prompt": …, "steps": …}` and nothing else (`adapters/image.py:88`). I printed the exact prompt that produced scene 3; it contains the literal line `- Pip: /media/assets/2cb81fc0-…/ecdb8189….jpg`. A text-to-image model cannot fetch that path, so the anchor image is inert — and worse than inert, because it injects a filename into a prompt whose whole job is to describe a picture. The brief's cross-cutting test ("consistency should collapse if references were removed") currently returns *no change*: `character_signature` deliberately excludes `reference_url` (`prompts.py:64-79`), so removing the block would not even move the cache key. `seed` is likewise accepted and then dropped (`adapters/image.py:87` explains why — flux-1-schnell rejects unknown fields). **Fix:** give the provider Protocol a capability flag (`supports_image_reference`) and emit the `REFERENCES:` block only for providers that can actually consume one; where it is emitted, send a URL the provider can reach, not a storage-relative path. Until a real image-conditioning provider exists, say so in `prompts.py` rather than letting the block read as a working consistency mechanism.

- [ ] **The negative prompt is not a negative prompt, and it demonstrably failed.** `NEGATIVE_TERMS` (`style.py:26`) is joined into prose and appended as an `AVOID:` section *inside the positive prompt*; the Cloudflare payload has no `negative_prompt` field. Diffusion models do not reliably parse negation, so `no text` and `no logos or watermarks` are being fed to the model as the tokens *text* and *watermark*. The receipt is in the live output: scene 3 has **"Pip" rendered as painted text** in the corner, and scene 2 carries a small glyph in the bottom-right that reads as a signature/watermark. §15.9's negative list is a *safety* control ("no realistic human children", "no scary imagery"), not only an aesthetic one, so "it is in the prompt somewhere" is not enough. **Fix:** pass negatives through the provider's real negative-prompt parameter where one exists (and record in the adapter which providers have one); for models with no such parameter, at minimum stop concatenating negations into the positive prompt, and add a post-render check for rendered text to the smoke harness's Check A.

- [ ] **Cross-child cache reuse points one family's storybook at an object under another family's storage prefix.** `storage.py:12-14` states the design plainly: the child id is in the key so that "delete everything you hold about my child" (§13.8/§17.5) is a *prefix delete*. But `_get_or_generate` step 2 copies `shared.url` verbatim onto the new child's row (`service.py:170-181`), so child B's portrait can live at `assets/<child-A-id>/<digest>.jpg`. The moment anyone implements the prefix delete that docstring promises, honouring family A's deletion request silently breaks family B's pictures. Nothing deletes stored objects today (`grep` for `storage.delete` → no call sites), so this is latent rather than live — which is exactly why it is cheap to fix now and expensive after Day 6 fills a bucket. **Fix:** either write shared assets to a content-addressed namespace with no child in the path and keep ownership entirely in the row (the digest already makes the key unique), or copy the object into the reusing child's prefix on reuse. Then add the deletion path with a test that deleting child A leaves child B's URLs fetchable.

### P2 — improvements (non-blocking, log for later)

- [ ] **Two concurrent requests for the same triple both pay.** Between the cache read (`service.py:142`) and the row write (`service.py:205`) there is no lock and no unique constraint on `(type, style_hash, character_hash, scene_hash)`. Two workers illustrating the same beat, or two children hitting the shared-render path at once, generate twice and store two rows. Harmless today (one companion, one sequential build task); worth closing **before Day 4 puts illustration on the story loop**, which is when parallel identical triples start happening. A `UniqueConstraint` plus `get_or_create` semantics is most of the fix.
- [ ] **A flagged asset re-pays the provider on every retry.** Any non-`PASSED` verdict raises `MediaBlocked` and writes nothing (`service.py:198`), so there is no negative caching: a provider that consistently returns something unrecognisable is billed on every attempt. Consider recording the blocked triple (with no URL) so a known-bad render is refused for free.
- [ ] **The model is not in the cache key.** `style_hash` is derived from `style_tokens()`, which carries `STYLE_VERSION` but not `IMAGE_MODEL` (`style.py:42`, `hashing.py:34`). Changing `IMAGE_MODEL` from flux-1-schnell to anything else serves every existing child their old art from the previous model — the exact interleaving `STYLE_VERSION` was introduced to prevent. Same shape on the audio side: the cache key is the *semantic* voice (`service.py:108`), so editing `ELEVENLABS_VOICE_MAP` or `ELEVENLABS_VOICE_ID` leaves every companion speaking in the old vendor voice forever. Fold the model id (and the resolved voice) into the hashed string.
- [ ] **Twelve orphaned objects are already on disk.** `media/assets/2cb81fc0-…/` holds 23 files but only 11 have a `Media` row; every row has its file, so nothing is broken — but `smoke_media --fresh` deletes the companion and repays for the set, and nothing ever deletes the bytes. On S3 that is a bill that only grows, and it is the same gap as P1-3. Add object cleanup alongside row deletion.
- [ ] **`prod.py` enforces `MEDIA_STORAGE=s3` but not `MEDIA_CDN_BASE_URL`.** Without the CDN base, `public_url` falls through to `media_storage().url(key)` (`storage.py:66-68`) and every child's device fetches the bucket hostname directly. `DEPLOY.md:63` documents the consequence honestly, but criterion 3 says "served via CDN URLs" — if that is the contract, `prod.py` should refuse to boot without it exactly as it does for `MEDIA_STORAGE`.
- [ ] **CI does not blank the media credentials the way it blanks the AI ones.** `ci.yml:53-54` sets `ANTHROPIC_API_KEY: ''` and `OPENROUTER_API_KEY: ''` with a comment explaining why, but nothing sets `CLOUDFLARE_API_TOKEN` / `ELEVENLABS_API_KEY` / `IMAGE_PROVIDER` / `TTS_PROVIDER`. `conftest.py` covers it for pytest, which is the only step that could call a provider, so this is defence-in-depth rather than a hole — but the two guards should look the same.
- [ ] **The review brief's own example `curl` 400s.** `docs/Review/Day3.md:10` posts `"palette":"violet","personality_preset":"warm_curious"`; the built catalogue is `ember/moss/tide/dusk/blossom` and `warm_guide/brave_spark/calm_anchor/curious_helper`. Rejecting unknown keys is correct behaviour (they would flow into an image prompt), but the brief will send the founder straight into a 400. Worth correcting the brief, or shipping the catalogue keys in the README.
- [ ] **The contact sheet reports `? · 0KB` for the four scene tiles** (`contact-sheet.html:82-95`) while the reference tiles show real content types and sizes. The images render, so this is cosmetic — but the content type is precisely what Check A exists to prove, and a founder skimming the sheet sees it missing on the tiles that show drift.
- [ ] **The companion's name is emitted twice in every prompt.** `descriptor.render()` prepends the name to the appearance and `CharacterRef.render()` prepends `"{name}: "` again, yielding `- Pip: Pip, a small, round-bellied dragon…`. Harmless, but it is doubled emphasis on a proper noun in a prompt that is already leaking text into renders (P1-2).
- [ ] **`docs/Build/Day3-smoke.md` is untracked.** The harness it specifies is committed (`8e4b9c7`); its brief is not. Every other day's brief is in git.

## Scope & risk notes

- **Front-running: none found.** No story generation, no beats, no memory, no evolution logic — `evolution_state` is written once as `{"stage": 0}` at creation and never read (`grep evolution` outside `evolution_state` returns only two comments explaining that the field exists so growth has somewhere to land). No safety hardening beyond the stub seam the brief asked for. The one change outside `companion`/`media` is `apps/story/ai/router.py` gaining `generate_structured()` — that is required by Build §4.3's "ask Claude to turn (archetype, name, palette) into a descriptor", and it correctly puts validate-and-repair on the *router* so a caller cannot opt out.
- **Architecture fidelity: good.** Adapters are Protocol-typed with one real implementation each (Cloudflare FLUX, ElevenLabs), a deterministic offline provider that is never a silent fallback (`select_image_provider` raises rather than degrading to placeholder art when a key is missing — `adapters/image.py:208`), and Together/OpenAI/Google declared as typed stubs that raise `NotImplementedError`. `django-storages` S3 backend is wired through a single `STORAGES["media"]` alias, so swapping S3 for R2/B2/MinIO is one settings block.
- **Storage hygiene: no blobs in Postgres.** Live `information_schema` dump of `media_media`: `id, created_at, updated_at, type, url, provider, prompt_hash, style_hash, character_hash, scene_hash, safety_status, bytes, child_id` — every column scalar, `url` a `character varying`. Django serves `/media/` only under `DEBUG and MEDIA_STORAGE != "s3"`, and `prod.py` raises `ImproperlyConfigured` on any other combination.
- **Cost posture: sound, with the caveats in P2.** The cache is correct, the reference set is generated once and reused forever, the greeting is one TTS call per child rather than one per session, and `smoke_media` reuses its fixture so a repeat run costs a single image. This review itself spent **zero** provider credits: `render_companion` came back entirely from cache and every write I made was rolled back.
- **Secret hygiene: clean.** No key material in the diff; `.env` untracked; `smoke_media`'s preflight names the missing variable without printing values. I read only variable *names* and lengths from `.env`, never values.
- **Working-tree state:** `d6fd1d0`, with `Docs/Build/Day4.md` modified and `Docs/Build/Day3-smoke.md` untracked — neither is Day-3 code.
